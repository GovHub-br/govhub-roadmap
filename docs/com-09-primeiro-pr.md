Ao final deste tutorial você vai ter uma contribuição aberta no GovHub — pequena, real e revisada.

Este é um **tutorial**: existe um caminho único e o resultado é garantido. As convenções completas ficam em [Padrões de commit / branch / PR / testes](#doc/com-02-padroes-commit-pr).

## Antes de começar

- Conta no GitHub
- Ambiente local rodando (veja **Instalação**)
- Assinatura de commits configurada

## 1. Escolher o que fazer

*A escrever: onde encontrar uma primeira tarefa — label de `good first issue`, correção de documentação, teste faltando. A primeira contribuição deve ser pequena de propósito: o objetivo é atravessar o processo inteiro, não resolver algo difícil.*

## 2. Fork e clone

*A escrever: fork pela interface do GitHub, clone do fork, configurar o remote `upstream`.*

## 3. Criar a branch

*A escrever: atualizar a partir do upstream, criar branch seguindo a convenção do projeto.*

## 4. Fazer a mudança

*A escrever: editar, rodar `make format` e `make lint`, rodar `make test`.*

## 5. Commitar

*A escrever: escrever a mensagem no formato adotado, commit assinado.*

## 6. Abrir o PR

*A escrever: push da branch, abrir o PR pela interface, o que escrever na descrição, marcar a issue relacionada.*

## 7. Responder à revisão

*A escrever: como ler os comentários, como aplicar as mudanças pedidas, o que fazer quando discorda. Esta etapa costuma ser a que trava quem chega — merece atenção especial.*

## 8. Depois do merge

*A escrever: apagar a branch, sincronizar o fork, onde procurar a próxima tarefa.*
